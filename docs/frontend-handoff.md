# 김지원 프론트엔드 — 1주차 연결 안내

## 화면 흐름

`접속 화면 → 로비(방 목록·생성·입장) → 채팅방(대화·참가자·퇴장)`

- `Theme`: 색상·폰트·버튼·입력창 공통 스타일.
- `ChatPanel`: CardLayout 화면 전환, 입력 검사, 요청 전송, 수신 이벤트에 따른 UI 상태.
- `ChatTransport`: 화면이 사용하는 공통 통신 인터페이스.
- `SocketTransport`: 실제 TCP 연결·HELLO·수신 스레드. 화면의 작업 스레드에서 쓰기를 실행.
- `DemoTransport`: 로컬 화면 개발용 예시 데이터. 다중 사용자·서버 저장을 흉내 내는 운영 서버가 아님.
- `Message`: 공동 프로토콜 초안의 프레임 읽기·쓰기.

## 이정윤님과 먼저 맞출 내용

1. JDK 17 이상 사용 가능 여부. 현재 코드는 JDK 25에서 `--release 17`로 컴파일했습니다.
2. 포트 5000, 길이 기반 프레임·Base64 필드 형식 사용 여부.
3. HELLO/WELCOME/ERROR와 방·채팅 메시지 필드·이벤트 순서.
4. 방 생성 시 자동 입장, 닉네임 중복 처리, 빈 방 처리 기준.
5. 테스트할 서버 IP·포트와 실행 방법.

상대에게 연락하거나 위 규칙을 합의한 상태는 아닙니다. 프로토콜 문서를 함께 검토한 뒤 확정하세요.

## 처음 연결하는 순서

1. 서버가 HELLO를 받고 WELCOME, ROOMS를 보내도록 구현합니다.
2. 프론트에서 데모가 아닌 **서버 연결**을 선택합니다.
3. 방 목록 → 생성·입장 → 참가자 목록 → 채팅 → 퇴장 순서로 연결합니다.
4. 같은 서버에 클라이언트 3개를 붙여 `docs/week1-checklist.md`를 확인합니다.

서버의 CHAT_MESSAGE에는 보낸 사람도 포함해야 합니다. 프론트는 서버 응답을 받은 뒤 대화에 표시하고 입력을 비웁니다. 서버가 다른 규칙을 사용하면 프로토콜과 클라이언트 처리를 같이 수정해야 합니다.
