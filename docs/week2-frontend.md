# 김지원 프론트엔드 2주차 시작

2026-11-13 사용자 확인: 2주차는 게임·이모티콘·귓속말, 할 일과 일정은 3주차로 진행한다.

## 귓속말 구현 범위

- 브랜치: `feature/frontend-week2`, 통합 main `7ea7021`에서 시작.
- 채팅 입력창의 `＋ → 귓속말`을 누르면 별도 입력 영역이 열린다.
- 같은 방의 자신을 제외한 참가자를 선택한다. 일반 대화 입력과 귓속말 입력은 별개다.
- `WHISPER_SEND(target, text)`를 보내고 `WHISPER_MESSAGE(roomId, from, to, text)`를 수신한다.
- 전송한 내용과 상대가 일치하는 자신의 응답으로만 전송 대기를 끝낸다. 그사이 수신한 다른 사람의 귓속말은 표시하되 전송 완료로 취급하지 않는다.
- 실패 시 초안을 유지한다. 상대가 퇴장해도 다른 상대를 자동 선택하지 않는다.
- 방 전환·퇴장·연결 종료 시 귓속말 입력을 비운다. 방 목록 미리보기에는 귓속말 내용을 넣지 않는다.
- 클라이언트는 다른 방이나 자신과 관계없는 귓속말을 표시하지 않는다. 실제 제삼자 전달 차단은 서버에서도 반드시 수행해야 한다.

기준: [팀원 노션 통신 규칙](https://app.notion.com/p/ChatApp-2-4158c3c90e8c803d9398ee0daebb256e), 2026-11-13 열람.
노션의 제안 규칙으로 프론트엔드를 먼저 준비한 단계이며 공동 합의나 서버 구현 완료를 의미하지 않는다.
공통 Message 프레임은 그대로 사용한다.

## 검증과 한계

`sh test.sh`: 기존 회귀 검사, 테스트 전용 TCP 상대를 이용한 귓속말·게임·이모티콘 검사, 애니메이션 수명과 로컬 데모 검사 총 175건 통과.
화면 캡처: `build/screenshots/08-week2-whisper.png` (자동 검사에서 렌더링한 화면).
다른 방·제삼자 이벤트 차단, 송신 필드, 응답 지연, 입력 분리, 오류 후 초안 보존, 퇴장 처리를 확인했다.
실제 팀원 2주차 서버와 다중 클라이언트 통합, 마우스 조작은 확인 전이다.
1주차 서버는 새 귓속말 요청을 지원하지 않는다. 로컬 데모는 아래의 가상 참가자 체험을 지원하며, 실제 TCP 수신 처리는 테스트 전용 TCP 상대를 통해 별도로 검사했다.

## 게임과 이모티콘 구현 범위

2026-11-13 김지원 확인: 게임은 시작 시점의 방 전원 참가 방식으로 진행한다.

- 입력창 왼쪽 ＋ → 가위바위보로 화면을 열고, 함께 시작을 누른다. 두 명 이상일 때 시작 요청을 보낸다.
- 서버 참가자 목록을 기준으로 선택 버튼을 활성화한다. 중도 입장자는 관전하며, 퇴장한 사람을 현재 참가자에서 제외한다.
- 선택 응답 뒤에는 채팅을 계속할 수 있다. 결과를 기다리느라 7초 뒤 연결이 끊기지 않는다.
- 서버가 공개한 선택과 승자를 표시한다. 복수 승자, 무승부, 시간 초과·인원 부족 취소를 처리한다.
- 이모티콘 창에서 보유 목록을 조회하고, 보유한 E01~E08만 보낼 수 있다. 단순한 캐릭터 그림 8종으로 표시하며 보상 알림과 중복 이벤트 처리를 연결했다.
- 새 보상 수신은 서버가 지급한 이벤트를 표시하는 동작이다. 무작위 지급·중복 지급 방지·서버 저장 정책을 프론트에서 대신 구현하지 않는다.
- 관련 코드: RoomGameView.java(상태와 결과), EmoticonPicker.java(보유 목록·선택), ChatPanel.java(요청·이벤트 연결).
- 추가 캡처: build/screenshots/09-week2-game-waiting.png, 10-week2-game-reward.png. 테스트 상대가 보낸 이벤트로 자동 렌더링한 화면이다.

## 입력창 도구와 게임 애니메이션

- 멤버 버튼은 참가자 목록만 표시한다. 입력창의 ＋는 가위바위보·귓속말 메뉴를 펼치고, 이모티콘 버튼은 보유 목록을 펼친다. 메뉴를 여닫아도 일반 채팅 초안은 유지한다.
- 가위·바위·보는 폰트에 의존하지 않는 벡터 손 그림으로 표시한다. 선택한 손은 커지고 테두리와 체크 표시로 구분한다.
- 대기 중에는 주먹이 움직이며 선택 완료 인원을 표시한다. 서버의 GAME_RESULT를 받은 뒤 약 1초간 가위→바위→보를 보여주고 참가자별 선택과 승자를 공개한다. 애니메이션이 승패를 판정하지 않는다.
- 게임을 접으면 애니메이션을 중단하고, 다시 열면 대기를 재개한다. 결과 공개 중 접으면 결과를 바로 표시한다. 퇴장·연결 종료 시 타이머를 정리하여 이전 결과가 새 방에 표시되지 않도록 한다.
- headless 자동 렌더링으로 1080×720, 960×680 화면을 확인했다. 실제 사용자의 마우스 조작 평가는 별도다.

## 서버 없이 직접 체험

```sh
cd ~/Network_Programming/팀프로젝트
sh run.sh
```

1. 닉네임 입력 → 먼저 둘러보기 → 우리들의 아지트에 입장한다.
2. 입력창 왼쪽 ＋ → 가위바위보 → 함께 시작 → 손 모양을 선택한다.
3. 가상 친구 둘의 응답과 결과 공개를 확인한다. 데모는 승리 → 무승부 → 가상 친구 둘의 승리 순서로 반복한다. 실제 서버 판정 검증이 아니다.
4. 이모티콘 버튼으로 기본 체험 항목 E01·E02와 획득한 보상을 전송할 수 있다. ＋ → 귓속말에서는 가상 친구의 자동 응답을 확인할 수 있다.
5. 다른 기본 방이나 새로 만든 방은 혼자 확인하는 방이다. 앱을 종료하면 데모 보유 항목·게임 상태는 사라진다.

## 그림 이모티콘

- 미소·좋아요·축하·감사·응원·인사·최고·박수의 8종을 같은 둥근 캐릭터로 그렸다. Java2D 벡터 그림이므로 외부 폰트나 이미지 파일 설치 없이 표시된다.
- 선택창에는 그림과 짧은 이름을 표시한다. 미보유 항목은 흐린 그림과 자물쇠로 구분하고 전송을 막는다.
- 채팅에는 말풍선 배경 없는 112px 스티커로 표시하며, 발신자·수신 시각·스크롤 동작은 유지한다. 복사와 접근성 설명에는 `[이모티콘: 이름]`을 제공한다. 일반 채팅에 입력한 ID 문자열은 그림으로 바꾸지 않는다.
- 그림 선택창과 게임 카드는 번갈아 표시해 작은 창에서도 대화 공간을 확보한다. 이모티콘 수신 시 방 목록에는 `[이모티콘] 이름`을 표시한다.
- 이번 변경은 표현 방식만 바꾸며 E01~E08 ID와 송수신 필드는 유지한다. 실제 팀원 서버와의 통합은 별도 확인이 필요하다.
