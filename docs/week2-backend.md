# 2주차 백엔드: 가위바위보·이모티콘·귓속말

`docs/protocol.md`는 프론트엔드 쪽 변경과 겹치지 않도록 이번 PR에서는 건드리지 않았습니다. 통신 필드는
`feature/frontend-week2`가 이미 구현한 것을 그대로 따랐고(`docs/protocol.md`의 "2주차 프론트엔드 연결
규칙" 절 참고), 서버 쪽 설명만 이 문서에 둡니다.

## 범위

가위바위보 판정·보상, 이모티콘 보유·전송, 귓속말. 방별 할 일·일정은 3주차 범위라 다루지 않았습니다.

## 메시지

`docs/protocol.md`의 표와 동일합니다. 서버 구현은 `Hub.gameStart` / `gameChoose` / `emoticonList` /
`emoticonSend` / `whisper`에 있고, `Session.dispatch`에서 연결했습니다.

## 정책 (현재 구현값)

| 항목 | 값 |
|---|---|
| 선택 제한 시간 | 30초 (`Hub` 생성자 인자로 조정 가능, 테스트는 짧은 값 사용) |
| 무승부·취소 보상 | 없음 |
| 보상 방식 | 승자 전원에게 미보유 중 무작위 1개, 8개 모두 보유 시 무지급 |
| 보유 저장 | 닉네임 기준 서버 메모리(`Hub`의 별도 맵), 서버 재시작 시 초기화 |
| 귓속말 범위 | 같은 방 안만 |
| 이모티콘 ID | `E01`~`E08` |
| 선택 후 퇴장한 참가자의 선택 | 버림 |

이 값들은 인계 문서(노션 제안)에 있던 제안값을 그대로 적용한 것으로, 지원님과의 최종 합의 전입니다.
바뀌면 `Hub`의 해당 부분만 고치면 되도록 구성했습니다.

## 게임 상태·동시성

- `Hub.Room`에 `Game game` 필드를 두고, 방당 게임은 최대 1개로 제한합니다(`GAME_BUSY`).
- `Game`은 시작 시점 참가자 집합(`Session` 참조, 닉네임이 아님 — 재접속 시 닉네임 재사용과 무관하게
  동작), 선택 맵, 타이머(`ScheduledFuture`)를 가집니다.
- 30초 타이머는 데몬 스레드의 `ScheduledExecutorService`로 구현했고, 콜백은 `Hub`의 `synchronized`
  메서드(`gameTimeout`) 안에서 실행됩니다. 콜백 시작 시 해당 게임이 아직 유효한지(`room.game`이 그
  게임인지) 다시 확인해 경쟁 조건을 피합니다.
- 참가자 퇴장(`ROOM_LEAVE`)과 접속 종료(`disconnect`)는 같은 경로(`Hub.leaveGame`)로 처리합니다.
  남은 참가자가 2명 미만이면 `GAME_CANCELED(PLAYERS_LEFT)`, 모두 선택을 마친 상태면 즉시 판정합니다.
  방을 나간 사람은 참가자 집합에서 바로 빠지므로 이후 어떤 게임 이벤트도 받지 않습니다.
- 이모티콘 보유 맵은 `users`와 별도로 두어 `disconnect()`에서 지우지 않습니다. 같은 닉네임으로
  재접속하면 보유 목록이 그대로 유지됩니다.

## 테스트

`sh test-server.sh`에 전부 포함했습니다(`src/test/java/chatapp/ServerChecks.java`). 기존 41건 외에
216건을 추가해 총 257건입니다.

- `whisperChecks`: 발신·수신만 전달, 제3자·다른 방 미수신, 자기 자신·같은 방 밖 대상 거부, 빈 본문 거부.
- `gameBasicChecks`: 혼자일 때 시작 거부, 진행 중 재시작 거부, 없는 게임·잘못된 선택·중복 선택 거부,
  무승부·단일 승자 판정, 보상 지급과 보유 목록 반영, 보유 이모티콘 전송.
- `gameThreePlayerChecks`: 3명 방에서 승자 여러 명 / 1명 / 세 종류 무승부.
- `gameLateJoinerChecks`: 중도 입장자는 `GAME_STARTED` 없이 결과만 수신, 선택은 거부.
- `gameLeaveDuringGameChecks`: 퇴장 후 남은 인원이 모두 선택한 상태면 즉시 판정, 2명 미만이면
  `PLAYERS_LEFT`로 취소.
- `gameDepartedPlayerSilentChecks`: 게임이 계속되는 동안 먼저 나간 사람에게는 이후 이벤트가 가지 않음.
- `gameFullEmoticonChecks`: 8회 연속 승리로 전부 보유한 뒤에는 이겨도 추가 지급이 없음.
- `gameTimeoutChecks`: 별도의 짧은 제한 시간(150ms) 서버로 시간 초과 취소(미선택자 1명 이하)와
  시간 초과 판정(2명 이상 선택)을 확인.

기존 1주차 검사(접속·방·채팅·느린 클라이언트 처리)도 그대로 통과합니다.

## 통합 검증 (남은 일)

이 PR은 서버 구현과 단위 테스트까지입니다. `feature/frontend-week2`와의 실제 연결 확인(클라이언트
3개·방 2개, 7절 공동 완료 기준)은 아직 하지 않았습니다. 다음에 확인할 때 특히 살펴볼 지점:

- 프론트는 요청 후 7초 안에 자기 응답이 없으면 연결을 끊습니다. 귓속말은 서버가 `clean()`으로 다듬은
  본문이 원래 보낸 본문과 달라지면 프론트가 응답으로 인정하지 않는데, 프론트가 이미 입력값을
  `strip()`해서 보내므로 보통은 문제가 없을 것으로 보이지만 실제 통합에서 한글 입력기(IME) 등으로
  달라지는 경우가 있는지 확인이 필요합니다.
- 노션 제안값(선택 제한 30초, 보상 방식, 귓속말 범위 등)은 지원님과 최종 합의 전입니다.
- 할 일·일정(3주차 범위)은 건드리지 않았습니다.
