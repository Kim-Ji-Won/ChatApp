## 구현

- 방 상단과 입력창 ＋의 **우리의 계획**에서 할 일과 약속을 한 목록으로 보여준다. 종류별 탭 없이 **+ 추가 → 할 일 / 약속**에서만 종류를 선택한다. 할 일은 원문 선택 안내를 거쳐 대화로 돌아가고, 약속은 바로 입력 폼을 연다.
- 일반 메시지 말풍선 우클릭 → **할 일로 만들기**: 발신자·본문 사본을 보관하고 제목, 담당자, 마감을 입력한다. 귓속말과 시스템 안내는 공유 원문에서 제외한다.
- 할 일 목록·생성·수정·삭제·완료/취소. 작성자만 수정·삭제, 작성자·담당자만 완료 변경할 수 있도록 UI를 조절한다. 삭제는 한 번 더 확인한다.
- 약속(통신에서는 SCHEDULE) 생성·수정·삭제와 여러 줄 메모. 날짜/시간은 달력과 시·분 선택기를 쓴다. 통합 목록의 날짜 필터는 할 일 마감일과 약속 날짜에 함께 적용하며, 날짜 칩의 ×로 전체 목록을 복원한다. 완료된 할 일은 아래로, 나머지는 날짜·시간 순으로 정렬하며 날짜 없는 항목은 뒤에 둔다.
- 목록 왼쪽 원형 표시를 누르면 상세를 열지 않고 완료·취소한다. 작성자·담당자만 가능하며 서버 응답 전에는 체크를 바꾸지 않는다. 처리 중 중복 클릭·더블클릭의 두 번째 동작·초안 작성 중 변경을 막는다. 충돌 시 상태를 유지하고 새로고침 후 재시도한다. TODO_COMPLETE의 UUID, ID, expectedRevision, 완료 값 형식은 유지한다.
- 한국 시간 기준으로 오늘·내일·어제·마감 지남·지난 약속을 표시한다. 완료한 할 일에는 마감 경고를 붙이지 않고, 시간 없는 오늘 항목은 하루가 끝날 때까지 지난 상태로 보지 않는다. 상세 입력은 정확한 날짜와 시간을 유지하며 상대 표현은 화면에서만 사용한다. 표시 중에는 30초마다 문구를 다시 그린다.
- 날짜 필터는 ‘모든 날짜 ▾’ 하나로 표시하고, 선택 후 날짜와 해제 ×를 같은 칩에 보여준다.
- 시간 팝업 안의 중첩 드롭다운을 제거했다. 시(0~23)·분(0~59)을 숫자 조절기의 화살표 또는 직접 입력으로 정하고 ‘선택’으로 확정한다. 범위 밖 입력은 팝업 안에서 안내하며 ‘시간 미정’으로 해제한다. 전송 형식은 HH:mm을 유지한다.
- 통신 규칙은 유지한다. TODO_LIST 완료 후 SCHEDULE_LIST(roomId, 빈 날짜)를 순차 요청하고 두 목록을 프론트에서 합친다. 필터는 전체 목록을 보관한 채 화면에만 적용한다. 종류+ID로 항목을 구분하여 같은 ID의 할 일과 약속이 충돌하지 않게 한다. 한쪽 조회 실패 시 부분 조회 오류를 안내한다.
- 생성·수정 성공 후 저장한 항목을 목록에서 선택하고 보이는 위치로 이동한다. 선택한 날짜 필터 밖에 저장된 경우에만 필터를 해제하고, 같은 날짜에 저장하면 필터를 유지한다.
- 목록에서 방향키는 선택만 이동하며 Enter로 상세를 연다. Space로 권한 있는 할 일의 완료·취소를 요청한다. 키를 누른 채 반복되는 입력은 한 번만 처리하고, 목록 갱신 뒤에도 선택을 유지한다. 마우스로 항목을 클릭하면 상세를 여는 기존 동작은 유지한다.
- 오류 안내는 길이에 따라 44~140px로 표시하고 더 긴 내용은 세로 스크롤로 모두 읽을 수 있다.
- 입력 오류와 서버 ERROR 뒤 작성 내용을 유지한다. 수정 중 다른 변경이 오면 저장을 막고 최신 내용 비교를 제공한다. CONFLICT 뒤에는 목록 재조회 → 최신 내용 확인 → 사용자가 재저장한다.
- 변경 알림의 roomId/requestId 및 revision 검사. END까지 목록 임시 보관, 날짜 조회 직렬화, 삭제 항목 부활 방지, 기존 2필드 ERROR와 신규 3필드 ERROR 호환.
- 빈 방/재입장 보존과 예시 데이터를 제공하는 로컬 데모. 데모는 화면 체험용으로 운영 서버나 실사용 데이터 저장소가 아니다.

## 서버 없이 확인

```sh
cd ~/Network_Programming/팀프로젝트
sh run.sh
```

1. 닉네임 입력 → **먼저 둘러보기** → **우리들의 아지트**.
2. **우리의 계획**에서 예시 할 일과 약속이 함께 보이는지 확인하고 할 일을 선택한다. 가상 친구가 작성하고 내가 담당자인 항목은 수정이 비활성화되며 완료는 가능하다.
3. 오른쪽 위 **×**로 대화로 돌아와 일반 메시지 전송 → 그 말풍선 우클릭 → **할 일로 만들기** → 담당자/마감 입력 → 등록.
4. 목록 왼쪽 원형 표시로 완료·취소를 확인하고, 내 할 일을 선택해 수정·삭제를 확인한다. 제목 오류 안내와 달력 선택을 확인한다.
5. **우리의 계획** → **+ 추가** → **약속**에서 제목·메모를 입력하고 달력과 시간 선택기로 일시를 정한다. 수정·삭제, 날짜 검색을 확인한다.
6. 방 퇴장·재입장 후 목록을 열면 데모 데이터가 유지된다. 연결 종료 후 새 데모 세션은 초기화된다.

처음 열면 통합 목록만 표시하고 항목을 클릭하거나 Enter로 열거나 새 약속을 추가할 때 상세·입력 화면을 연다. 오른쪽 위 × 또는 Esc로 대화로 돌아간다. 닫아도 같은 방에서는 작성 중인 입력을 유지하며 다시 열면 이어서 작성할 수 있다. ‘← 목록’으로 이동한 경우 ‘작성 중인 내용 이어서 보기’로 복귀한다. 원문은 ‘원문 보기’로 필요할 때 펼친다. 정상 처리 로그는 상시 표시하지 않고 입력 오류·충돌 안내는 필요한 순간에 표시한다.

작은 창에서는 폼 내부를 스크롤한다. 저장·삭제·최신 확인 버튼은 폼 아래에 고정된다. 편집 중 다른 항목을 선택하려면 저장하거나 입력 취소를 먼저 누른다. 방 퇴장·연결 종료 시 폼은 초기화되며 디스크에 저장하지 않는다.

## 검증

`sh test.sh`는 기존 FrontendChecks와 신규 Week3Checks를 실행한다. Week3Checks의 TCP 상대는 임시 포트에서 지정된 응답·오류·충돌을 보내는 검사용 코드다. 실제 팀원 서버와의 통합 결과가 아니다.

2026-11-19 통합 화면 확인: 기존 FrontendChecks **175건** + Week3Checks **210건**, 총 **385건 통과**. Java 17 대상으로 빌드했다. 아래 항목을 자동 검사했다.

- 두 종류의 목록 순차 요청, 통합 표시, 동일 ID의 할 일·약속 구분 및 요청 종류 유지.
- 추가 시 종류 선택, 원문 안내, 상세 화면의 종류별 입력·권한·완료 버튼.
- 날짜 필터에 두 종류를 함께 적용하고 원본 목록 유지, 칩의 ×로 전체 날짜 복원.
- 목록 원형 영역의 마우스 이벤트로 완료/취소 요청, 권한·초안 보호, 응답 전 상태 유지, 중복 클릭 차단과 충돌 복구.
- 고정 시각을 이용한 오늘·내일·어제·마감 분 경계·자정·정오·완료 항목·연도·잘못된 날짜 표시 검사.
- 한쪽 목록 조회 실패 후 대기 해제와 오류 안내, 이후 채팅·재조회 유지.
- 닫기·Esc·초안 복원·다른 종류 선택 시 초안 보호, 오류·충돌 비교, 방 격리.
- 달력 윤년·연말 이동·한국 날짜·시간 해제·분 단위 보존·권한별 비활성화.
- 시간 숫자 조절기 내부 화살표 증감·하한/상한·직접 입력 오류·수정 후 확정. 사용자가 보고한 macOS 드롭다운 클릭 시 팝업 소멸은 중첩 팝업 제거로 대응했다. 자동 조작 도구는 Java 앱에 접근하지 못했으며, 수정 후 사용자가 직접 실행해 시간 선택이 정상 동작한다고 확인했다.
- 필터 밖 할 일·약속 생성/날짜 수정 후 필터 해제와 해당 항목 선택, 같은 날짜 수정 시 필터 유지.
- 긴 서버 오류의 스크롤 범위와 마지막 안내 접근, 오류 이후 입력 보존.
- 방향키·Enter·Space 바인딩, 키 반복 차단, 대기 중 목록 초점 유지, 실시간 갱신 후 선택 유지.

## 실제 서버가 준비되면 공동 확인

- 클라이언트 3개·방 2개에서 할 일·일정 생성/수정/삭제/완료가 같은 방에만 반영되는지.
- 작성자·담당자·다른 참가자 권한을 서버가 독립적으로 검증하는지.
- 두 창 동시 수정의 CONFLICT와 초안 유지, 최신 내용 확인 후 저장.
- 담당자 퇴장 뒤 기존 담당자 유지 수정, 빈 방 재입장과 목록 복원.
- 목록 START/END 순서, 필터 조회와 실시간 변경, 이전 방 이벤트 차단.
- 중복 requestId와 다른 payload, 방 이동 뒤 캐시 응답 차단, 재접속 시 자동 생성 재전송 없음.
- 서버 재시작 시 데이터 초기화와 기존 채팅·게임·이모티콘·귓속말 회귀 확인.

현재 저장소 서버는 2주차 구현이다. 3주차 서버 통합 완료로 표시하지 않는다. 자동 화면 렌더링과 실제 마우스 조작 확인도 구분한다.
